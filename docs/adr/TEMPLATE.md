# ADR-NNNN — Short decision title

**Status:** Proposed · **Date:** YYYY-MM-DD · **Review:** YYYY-MM-DD (or "framework boundary")

## Context

What forces a decision now? Name the package, dependency, framework boundary, or peer
capability. Include the date the evidence was checked and the version that was checked.

## Decision

State the decision in one or two sentences. Say explicitly what we will and will not do; a
"non-goal" without a dated revisit trigger is not a valid ADR.

## Consequences

- What becomes possible.
- What becomes impossible or deferred.
- Which packages, target frameworks, or users are affected.
- How the decision is verified (test, CI gate, package inspection).

## Revisit trigger

State the concrete event that would reopen this decision (a dependency publishes a TFM, a
security advisory lands, a peer changes its license) and a **target review date**. If the
decision is a permanent framework boundary, say why no date-based review is planned.
