# Jeninnet.CQRS v1.0.0-preview.1 — First Public Preview

`v1.0.0-preview.1` is the first public preview of **Jeninnet.CQRS**, a modular CQRS and messaging
framework for .NET. It packages the completed 78/78 parity tree as **31 NuGet packages**: a
source-generated dispatch core, opt-in pipeline behaviors, durable messaging primitives, sagas,
transports, serializers, diagnostics, and testing tools.

This is a preview, not a stable API declaration. Pin `1.0.0-preview.1` exactly when you evaluate it,
and expect the public surface to evolve before `1.0.0`.

## Highlights

### Source-generated registration and dispatch

The core package discovers handlers at compile time through the Roslyn generator instead of relying
on runtime assembly scanning. Registration stays explicit, startup work stays small, and the
generated path is covered by the AOT smoke sample. The analyzer and generator packages are shipped
separately so a consumer can adopt the runtime without the tooling, or the tooling without the
runtime.

### One command/query/notification surface

Commands, queries, notifications, streams, and request/response handlers share one broker and one
registration model. The package family is layered rather than monolithic: the core, contracts,
ASP.NET Core integration, validation, caching, resilience, idempotency, transactions, diagnostics,
health checks, and rate limiting can be adopted independently.

### Durable messaging without a mandatory infrastructure choice

The preview includes outbox and inbox abstractions, deferred and scheduled delivery, recurring jobs,
dead-letter storage, claim check, sagas, and saga persistence. The transports are opt-in:
AWS SQS/SNS, Azure Service Bus, Kafka, RabbitMQ, MQTT, HTTP, and SignalR. The same handler contracts
survive a transport change; the infrastructure package changes, not the application model.

### Serialization and result adapters

System.Text.Json is the default path, with Newtonsoft.Json and MessagePack packages for systems that
need them. Result adapters for CSharpFunctionalExtensions, ErrorOr, and FluentResults keep the
pipeline independent of a single result library.

### Quality gates are part of the release

The preview was packed with package validation enabled, verified at **31 packages and 29 symbol
packages** (the analyzer and generator packages intentionally produce no symbols), built with
0 warnings / 0 errors, tested across the solution, documented with DocFX, and exercised by an AOT
smoke sample. The package metadata carries the repository, license, README, and icon.

## What this release is about

The release is not a feature-count milestone. It is the point where the framework's separate
decisions become one coherent surface:

- handlers are registered by the compiler, not by reflection;
- behaviors are opt-in and composable;
- durability is a set of packages, not a hidden dependency;
- transports are interchangeable at the boundary;
- the public packages carry the same version and release identity.

That is the contract this preview asks consumers to evaluate.

## Compatibility

- **Version:** `1.0.0-preview.1`; pin the exact preview version.
- **Runtime targets:** `net10.0` and `net11.0`; `netstandard2.0` for portable packages and `net462`
  for the dispatch/observability surface where documented.
- **Breaking changes:** there is no earlier public release to migrate from. The preview API may
  change before `1.0.0`; read the package README and release notes before upgrading.
- **Symbols:** 29 symbol packages are published; `Jeninnet.CQRS.Analyzers` and
  `Jeninnet.CQRS.Generators` are analyzer-only by design.
